### 原因と修正

- 旧UIではOfferとfallbackを同時に出力した。今は商品ごとの `resolveCommerceState` で、Affiliate → 通常直 → 検索のうち選択した1つだけを表示。Amazon・蔵元の導線は別枠として維持。
- 旧サーバーは既存素材、回収した直リンク、回収画像を別々に評価し、一部の画像が購入可否に従属していた。今は同一resolverで判断し、SKU・容量・媒体・許諾・確認日時を検証したうえで、画像と購入を独立して決める。欠品・ページ消滅による購入停止だけでは、画像を消さない。明示的な画像停止・期限切れは非表示になる。
- 有効な同種承認が重複すれば `CONFLICT`、容量や版が違えば承認無効。持ち時間は画像・直リンクごとに管理。静的HTMLは検索のみを初期表示し、ブラウザが有効期限を確認してから正しい購入ボタンに切り替える。再表示やクリック時にも期限を確認する。
- 歴史資料のVercel承認や準備用の旧コードを、承認の証拠に使っていない。新判定が読む承認はNetlifyの正式媒体だけ。従来の正式素材・承認・期限・商品・推薦・料理データは変更していない。

全484件で登録媒体、期限、fingerprint／SKU、容量、在庫、重複承認、Vercel runtime依存の矛盾は0件。ルート排他性 **PASS**、合計387＋3＋94＝484 **PASS**、Vercel runtime approvals 0 **PASS**。期限後の全件シミュレーションでも失効リンク・画像の表示0件 **PASS**。旧HTMLと移行後の全件は `commerce-before.json` と `commerce-after.json`。
