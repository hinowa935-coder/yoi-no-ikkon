# 日本酒カタログ運用方針

## 情報源と公開

- 発見は楽天、商品同定は公式・業界団体・専門酒販、飲んだ感想は独立した実飲情報で補強する。
- 公式個別商品ページ未取得は即不採用にしない。商品単位の信頼できる複数資料、値単位の出典、medium以上の主要仕様を必要とする。
- 小売説明を自動でVerifiedに転記しない。口コミ・編集意見は商品仕様のVerifiedに入れない。
- 原料米の名前が異なるシリーズ、生/火入れ、原酒、無濾過、にごり、発泡、搾り方、季節商品、別ブランドは別SKU。未知はfalseにしない。
- 数値・ラベル・ロットの違いは両値を記録し、原因未確定とする。値の追加や「リニューアルしたはず」の断定は禁止。
- 720mlのリンクと1800ml画像を組み合わせない。容量選択型は実際の選択肢を確認する。
- 新規商品は実在庫、正式affiliate、正式画像原本、同じSKU・容量、料理と夜、重複確認、QAがそろってから手動で公開する。
- 従来商品を新ゲートで機械的に削除しない。総数固定や都道府県数合わせの置換をしない。

## 候補プール

`data/catalog-operations/candidates.json` が継続審査の台帳。
RESEARCHからACTIVEまでの段階、項目別ステータス、URL、itemCode、店舗、容量、季節性、出典、差分、保留理由、確認日を持つ。
未掲載名53枠は一次候補。企業グループ、法人名変更、同ブランド別蔵の確認完了数とは別集計。

公開承認は商品のID・正式画像原本hash・SKU/容量・登録サイト・有効期限・直近在庫・QAに結び付ける。
`publicationGate` は公開時点の判定、`validateCandidate` は保存された審査記録の整合性検査。
巡回は公開承認を発行しない。

## 口コミ

- 商品、版、生火入れ、日付、実飲、具体性、独立性、重複を確認する。
- 同一文章の転載、同じ発信者の複数投稿は独立票を増やさない。
- 配送・包装・贈答・星だけ・実飲不明は味の根拠から除外する。
- 3年以上前は現行設計の再確認がない限り合意形成から除外。未来日付も除外。
- 1件は個人の感想。複数独立情報の一致はmedium、公式との一致もある複数情報はhighになり得る。相反する情報を多数決だけで消さない。
- `sensoryConsensus` は編集上の合意整理で、Verified仕様ではない。
- 本文の大量転載・レビュワーのプロフィール化をしない。短い独自要約と元URLを保存する。
- レビュー数・星・価格・画像有無・affiliate有無を推薦順位に使わない。

## 料理・温度

`officialPairings` / `communityPairings` / `editorialPairings` を分ける。
具体的料理のcommunity採用は複数独立情報と料理構造の整合を重視し、1件は弱い補助情報にとどめる。
秋刀魚の塩焼きの感想を全魚料理へ自動拡張しない。
公式温度、小売の推奨、community温度も分ける。
今回の越乃景虎は公式料理0・community料理0、編集料理3。口コミ3件のうち合意形成対象1件で、強い合意軸0。

## ライフサイクル

`src/data/catalogLifecycle.json` はACTIVE/INACTIVE/ARCHIVEDの管理。
省略された既存IDはACTIVE。全件を`allSakePairings`に残し、通常検索・Discoverは`visibleSakePairings`で絞る。
INACTIVE/ARCHIVEDの詳細とおちょこ参照を保持。ARCHIVEDはnoindexにできる。
旧年から翌年へID・お気に入りを自動移行しない。別SKUへ自動redirectしない。
現在の季節名だけで非公開にせず、一時売切れ・季節終了・終売・不明を区別する。

## 巡回コマンド

production Git checkout内から実行する。

```powershell
node scripts/catalog-monitor.mjs
```

保存済み観測を再比較する。HTTP/API通信なし。

```powershell
node scripts/catalog-monitor.mjs --live
```

既存候補の楽天通常URLを直列に再確認する。リクエスト開始間隔1150ms以上。
画像取得・画像ダウンロード・affiliate生成・注文操作はしない。
429/401/403は停止。リダイレクトは自動追跡せず要確認。
本文・購入JSONが読めないことを売切れとしない。
商品内部IDと通常URLの両方を確認し、他商品のカート情報を在庫に流用しない。
仕様検出は差分ヒントであり、Verifiedへの自動反映ではない。

書込み先は観測、review queue、巡回実行記録、私有キャッシュだけ。
実行前後で商品データ・commerce・公開ファイルのhashを比較する。
不変スナップショットはイベント0。取得失敗も同じ失敗なら繰返しキュー追加しない。
新しい商品や蔵元の探索は`source-plan.json`の検索計画と今回のAPI管理スクリプトを使い、既存候補を上書きせず別候補として審査する。
今回、週次ジョブは有効にしていない。将来週1回を目安に設定する場合も自動公開権限は付与しない。

- 蔵元数は保守的な正規化枠。全法人・物理蔵・グループの完全名寄せではない。
- 新規正式画像・直リンク率100%の分母は今回公開の1商品。53候補全体ではない。
