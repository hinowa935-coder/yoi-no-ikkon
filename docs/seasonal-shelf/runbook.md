# 季節ごとの酒棚更新

年4回の大きな手動更新。自動公開・自動非表示・週次巡回は無効。春2月後半〜3月、夏5月後半〜6月、秋8月後半〜9月、冬11月後半〜12月が目安。20〜50本の入れ替えはノルマではない。

1. 本番のコミット・サイトマップ・検索/詳細UIを確認し、ACTIVE/総DB/旧参照・蔵元・地域・直リンク・画像・候補を再集計する。
2. D→B/C→Aの順に調査。4群とは別にSKU・味・ペアリング・在庫・期限を確認する。
3. 既存の購入先を先に救済し、検索0/取得失敗/一店舗売切れ/終売を区別する。
4. 季節酒・未掲載蔵をRakuten-Firstで候補へ。正式画像・同容量・現行SKU・味・料理・夜を審査する。価格や広告報酬を推薦点へ使わない。
5. 追加と棚下げを一つの計画にし、商品データやお気に入りを削除・別SKU移行しない。新SKUは新ID。翌年同名だけで分割/統合しない。
6. 読取専用のplan-seasonal-shelfで計画を確認。--applyは非対応。審査済み変更は通常のコードレビュー・tests/typecheck/lint/build・秘密値検査・本番デプロイ・公開URLでQAを行って反映する。
7. 30項目のレポートと差分・根拠・保持した旧URLを保存して停止する。

内部審査期限が季節窓より早ければ軽い手動確認を別管理する。2026年秋の最早期限は11月13日、手動確認目安は11月6日。期限の無確認延長、スケジューラーの勝手な有効化は禁止。
