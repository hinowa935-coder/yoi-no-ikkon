## 編集内容

- 全492件の初稿を通読し、語句のつながり、温度条件、開栓前後の順序、品種名と香りの混同を確認。
- 原則1〜2文。商品名の繰り返し、数値スペックの詰め込み、根拠のない料理・情緒表現は追加していません。
- 6種類の接続・文末パターンに加え、31商品を個別編集。異なる文章に見せるための形容や味覚の創作はしていません。
- 「米の旨味」「コク」のような根拠だけから、柔らかさ・透明感・上品さなどを足しません。
- 「夢の香」「佐香錦」等の米名は香りとして扱わず、必要な場合だけ確認済み原料米として記載。
- 冷酒・常温と燗の違い、開けたてと開栓後の変化は条件を保って編集。
- 料理提案の本文に重ねていたサービス名を省略。既存の「宵の一献の提案」ラベルは維持。

削除・置換した調査文体: 「『…』と紹介される味わい」「蔵元が…との相性を紹介している」「蔵元が紹介する…を手がかりに」「食事と楽しむお酒という紹介を手がかりに」。
以前から紹介文に多かった「特徴を読点で並べて終える」形も自然文へ変更しました。
「公式では」「蔵元によると」「商品説明では」「と案内されています」等も禁止表現として、表示用文章の検査対象に含めています。

出典欄、蔵元情報、公式の料理相性を区別する見出しは削除していません。そこにある「公式」「蔵元」「紹介」等は、情報源や主体を示す必要のある表記です。

## 根拠の追跡

紹介文はsrc/data/sakeIntroduction.jsで表示用に組み立て、各文にfactsを対応させています。
味わいはflavorProfileの値とfieldEvidence、またはverifiedFeatureTagsとfeatureEvidenceに直接対応します。
editorialTagsは商品の味わい紹介の入力に使用していません。
最低限の分類・蔵元紹介は、凍結DB内の確定フィールドと値単位のfieldEvidenceへ照合しています。

- before.json: 変更前の492文、料理提案、DBハッシュ、順位検査用ハッシュ。
- audit.json: 全492文のBefore/After、文→フィールド→値→URL・ソース種別・元の確認日、全料理提案のsignal。
- all-products.md: 全492商品の文章と使用したフィールドを読みやすく列記。
- browser.json: ブラウザ確認と公開用HTMLの監査結果。

これらは既存出典への参照記録です。新しいVerified情報として登録したものではありません。

## 重複・情報不足の扱い

確認済み情報が同じ商品に、違う特徴を作って文章を差別化することは避けました。
最低限の分類等だけの同文グループ: 7組。
味わい紹介の同文グループ: 7組。すべて、既存の同じ短い特徴を使う2商品の組です。
同文があることを隠さずaudit.jsonに全IDを保存しています。
情報不足を文章量で埋めるための新規調査は、今回の対象外として実施していません。
